# Token Naming Checklist

## 1. Structure

- [ ] Follows established taxonomy (e.g., Category-Property-Concept-Modifier).
- [ ] Uses consistent casing (e.g., kebab-case).

## 2. Abstraction

- [ ] Global/primitive tokens are semantic-free.
- [ ] Alias/semantic tokens clearly describe purpose.
- [ ] Component tokens isolate specific UI element properties.

## 3. Maintenance

- [ ] Documentation explains the naming convention.
- [ ] Deprecated tokens are marked correctly.
