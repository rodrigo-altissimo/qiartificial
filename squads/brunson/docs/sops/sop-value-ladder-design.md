# SOP: Value Ladder Design

## Purpose

Design a complete Value Ladder that moves customers from first contact to highest-ticket offer through ascending value, price, and intimacy. This SOP ensures no gaps exist in the product ecosystem and every rung naturally leads to the next.

---

## Prerequisites

- Completed Secret Formula (WHO, WHERE, BAIT, RESULT defined)
- Clear understanding of your market and competitors
- At least one existing product or service to anchor the ladder
- Access to competitor pricing research

---

## Step-by-Step Procedure

### Step 1: Audit Current Offers (30 min)

1. List every product and service you currently sell
2. Categorize each by price point: Bait ($0-50), Frontend ($100-2K), Middle ($2K-10K), Backend ($10K+)
3. Identify which rungs have products and which are empty
4. Note current conversion rates between existing offers

### Step 2: Define the Transformation Spectrum (45 min)

1. Write the BEFORE state of your dream customer (pain, frustration, current situation)
2. Write the AFTER state (dream outcome, transformed life)
3. Break the transformation into 4 progressive stages, one per rung
4. For each stage, define: what they learn, what they achieve, what they still need

### Step 3: Design Each Rung (60 min)

**Rung 1 -- BAIT ($0-50):**
- Format: Lead magnet, free + shipping book, tripwire, quiz
- Outcome: Quick win that proves your expertise
- Delivery: Fully automated, instant access
- Validation: "Would my dream customer trade their email/money for this?"

**Rung 2 -- FRONTEND ($100-2,000):**
- Format: Online course, digital product, software subscription
- Outcome: Meaningful progress toward the full transformation
- Delivery: Self-paced with some support
- Validation: "Does this naturally make them want more?"

**Rung 3 -- MIDDLE ($2,000-10,000):**
- Format: Group coaching, mastermind, certification, live event
- Outcome: Significant transformation with guided support
- Delivery: Group-based, scheduled, high-touch
- Validation: "Can I deliver this profitably at this price?"

**Rung 4 -- BACKEND ($10,000-100,000+):**
- Format: 1-on-1 consulting, done-for-you, private implementation
- Outcome: Complete transformation, fully customized
- Delivery: Personal, bespoke, premium
- Validation: "Is the result worth 10x+ the price to the right client?"

### Step 4: Design Ascension Triggers (30 min)

For each rung transition, define:
1. What signal indicates readiness to ascend (completed course, hit a result, asked for more)
2. How you will present the next rung offer (email, call, event, upsell page)
3. What timeline between purchase and next offer is optimal
4. What messaging bridges current rung to next rung

### Step 5: Map the Funnel Architecture (30 min)

1. Select the appropriate funnel type for each rung (refer to Nine Core Funnels)
2. Sketch the page flow for each funnel
3. Identify where funnels connect to each other
4. Define the email sequences that bridge between funnels

### Step 6: Price and Value Test (30 min)

1. Research competitor pricing at each rung
2. Ensure 10x value gap (perceived value vs. price) at every level
3. Create payment plan options for Middle and Backend rungs
4. Set revenue targets per rung based on expected conversion rates

---

## Quality Checks

- [ ] All four rungs are populated (no gaps in the ladder)
- [ ] Each rung naturally leads to the next (no disconnected offers)
- [ ] Price progression is logical (no rung costs less than the one below it)
- [ ] Value/intimacy increases with each rung
- [ ] Total LTV calculation: (Bait price x conversion to FE) + (FE price x conversion to Mid) + (Mid x conversion to BE)
- [ ] Ascension triggers are defined for each transition
- [ ] At least one funnel type identified per rung

---

## Handoff

Deliver to the team:
1. **Value Ladder Map** -- Visual diagram showing all four rungs with offers, prices, and formats
2. **Ascension Trigger Document** -- When and how to present each next-level offer
3. **Funnel Architecture Sketch** -- Which funnel type serves each rung
4. **Revenue Model** -- Expected revenue per rung based on conversion assumptions
5. **Priority Action List** -- Which rung to build/improve first (usually the missing one)
