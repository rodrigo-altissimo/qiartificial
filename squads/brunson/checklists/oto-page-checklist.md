# OTO Page Checklist (One-Time Offer / Upsell Page)

> Agent: brunson-pages
> Source: DotCom Secrets - Upsell/Downsell & Funnel Architecture
> Version: 1.0
> Use: When building or auditing a One-Time Offer (upsell/downsell) page

---

## Pre-Requisites
- [ ] Frontend offer purchase flow confirmed working
- [ ] OTO offer defined (complements the frontend, does not compete)
- [ ] Price point set relative to frontend purchase
- [ ] One-click upsell technology configured (no re-entering payment)
- [ ] Downsell variant prepared if buyer declines

---

## STEP 1: Page Header & Context

### 1.1 Congratulations Bridge
- [ ] Page opens by confirming the previous purchase ("Congratulations!")
- [ ] Validates the buyer's decision ("Great choice")
- [ ] Transitions naturally: "Before you go, there's one more thing..."

### 1.2 Headline
- [ ] Headline introduces the OTO as a natural next step
- [ ] Frames the OTO as enhancing or accelerating the core purchase
- [ ] Creates urgency ("This offer is only available right now")

---

## STEP 2: OTO Positioning

### 2.1 Logical Complement
- [ ] OTO solves the NEXT problem after the frontend offer
- [ ] Clearly explained why this enhances what they just bought
- [ ] Buyer can see how OTO + frontend = better results
- [ ] Does NOT make the frontend feel incomplete without it

### 2.2 Speed/Ease Angle
- [ ] OTO is positioned as getting results faster
- [ ] Or: removes a barrier/difficulty from the core offer
- [ ] Or: provides done-for-you or shortcut element
- [ ] Buyer feels this is a smart addition, not a separate purchase

---

## STEP 3: Offer Presentation

### 3.1 Value Stack (Abbreviated)
- [ ] OTO components listed clearly
- [ ] Dollar values assigned to each component
- [ ] Total value stated before price reveal
- [ ] Shorter than the main sales page stack (quick decision)

### 3.2 Price & Anchor
- [ ] Price anchored against value and standalone retail price
- [ ] Positioned as a special "add-on" price (only available now)
- [ ] Price point feels like a no-brainer given what they already bought
- [ ] Payment plan option available if price is above $97

---

## STEP 4: Urgency & Close

### 4.1 True One-Time Offer
- [ ] Clearly stated this price is only available NOW
- [ ] Timer or "this page will not be shown again" language
- [ ] Consequence of declining is explicit (will pay full price later)

### 4.2 CTA Buttons
- [ ] "Yes" button is prominent, positive, benefit-focused
- [ ] "No thanks" button is present but uses loss language
- [ ] Example: "No thanks, I don't want faster results"
- [ ] One-click purchase (no re-entering card details)

### 4.3 Guarantee Reminder
- [ ] Same or similar guarantee as frontend offer
- [ ] Risk reversal restated briefly
- [ ] Buyer feels safe adding this on

---

## STEP 5: Downsell Preparation

### 5.1 Downsell Path
- [ ] If buyer clicks "No thanks," downsell page is ready
- [ ] Downsell is a reduced version (fewer components, lower price)
- [ ] Or: downsell is a payment plan for the full OTO
- [ ] Downsell page follows the same structure (abbreviated)

### 5.2 Flow Integrity
- [ ] After OTO acceptance --> next step in funnel (OTO2 or thank you)
- [ ] After OTO decline --> downsell page
- [ ] After downsell acceptance or decline --> next step or thank you
- [ ] No dead ends in the funnel path

---

## Validation
- [ ] Full upsell flow tested (purchase frontend --> see OTO --> accept/decline)
- [ ] One-click purchase works without re-entering payment
- [ ] Downsell triggers correctly on decline
- [ ] Page loads quickly (buyer patience is LOW on OTO pages)
- [ ] Mobile-responsive and tested on phone

---

## Scoring
- 26-30/30 = Launch-ready OTO page
- 20-25/30 = Solid OTO, refine urgency and positioning
- 14-19/30 = Needs work on offer logic or flow
- Below 14 = Redesign OTO offer and page
